# convert

Converter from rAthena scripts to wAthena Lua and data (strategy section 5.6). It converts item scripts, and NPC scripts and shops.

- `parse.go` reads rAthena's script language, following `src/map/script.cpp`.
- `equip.go` runs equipment scripts symbolically. A condition on a game value, such as the refine level, becomes the `when` option of the bonus. A game value in an amount becomes a computed bonus.
- `use.go` translates scripts that run once: use handlers, equip and unequip scripts, and the effects of `autobonus`.
- `usestatus.go` converts `sc_start`, `sc_start2`, `sc_start4` and `sc_end` to `player:start_status` and `player:end_status` (proposal 0002, review decision 19), and `bonus_script` to `player:add_timed_bonuses`. Item scripts set `keep_duration`, as rAthena's default flag for items is `SCSTART_NOTICKDEF`. A timed bonus's key is a hash of its script's text, as rAthena tells `bonus_script` copies apart by their text. The flags `BSF_FORCE_REPLACE` (0x400) and `BSF_FORCE_DUPLICATE` (0x800) become `on_repeat = "extend"` and `on_repeat = "add"`. Without them, the API's default keeps the first copy, as rAthena does.
- `status.go` converts the scripts of `status.yml`, such as `bonus bStr,getstatus(SC_INCSTR,1);`, to bonus templates that `statuschange` computes for each active status ([decision 0010](../../docs/decisions/0010-status-effects.md)).
- `randomopt.go` converts rAthena's random options and groups from `random_options.json` to core's `data/random_options.yml` and `data/random_option_groups.yml` (proposal 0002, review decision 23, and [decision 0014](../../docs/decisions/0014-rolled-items.md)). An option's script converts as a status script does: `getrandomoptinfo(ROA_VALUE)` becomes `{ roll: value }`, a division or a minus around it `divide` or `multiply: -1`, and a `for` loop unrolls. Its readable name and display name come from its first bonus. `wactl convert random-options --report docs/generated/random-options-<mode>.md` writes the coverage report, which `TestRandomOptionReportsCurrent` checks.
- `bonusmap.go` maps every bonus form to a `bonuses.add` call of [proposal 0002a](../../docs/proposals/0002a-bonus-names.md): names, sign flips, chance units, argument order, and options. An autospell's `i` flag becomes an explicit `target`: for `bAutoSpell` and `bAutoSpellWhenHit`, bit 1 casts on the enemy and its absence on the wearer, as `pc_bonus_autospell` reads it; for `bAutoSpellOnSkill`, bit 1 casts on the wearer.
- `output.go` writes core's `data/items.yml` and `scripts/items/*.lua`. Equipment with only constant bonuses becomes item data.
- `report.go` writes the coverage report.

`waserver` runs the converter when it starts ([decision 0007](../../docs/decisions/0007-converted-item-scripts.md)). `wactl convert items` writes the files and the report:

```text
go run ./tools/wactl convert items --mode renewal --out /tmp/core-items
go run ./tools/wactl convert items --mode renewal --report docs/generated/item-scripts-renewal.md
```

Tests:

- `TestRunConvertedScripts` loads and runs every converted script of both modes, with equipment against a recording bonus sink.
- `TestEquipmentParity` equips every fully converted equipment item and card, with its static bonuses and its Lua script, on the recorder's sample player, and compares the stats and the damage with rAthena's `item_bonuses.json`, and every refine level with `refine.json`, in both modes. The results are `testdata/equipment_parity_<mode>.md` (server/README.md, "Equipment").
- `TestHealParity` checks that every plain heal converts to the amounts the items extract read.
- `TestGolden` keeps the output of sample items in `testdata/golden`.
- `TestStatusScripts` converts every status script of both modes and keeps the templates in `testdata/golden/status_scripts_<mode>.txt`.
- `TestReportsCurrent` checks the reports in `docs/generated`.

NPCs ([decision 0008](../../docs/decisions/0008-converted-npcs.md)):

- `parse.go` also reads NPC scripts: labels, `goto`, `menu`, `callsub`, `function` and `switch`. As rAthena's parser does:
  - Statements before the first `case` of a `switch` run after the value is read and before the cases are compared.
  - The condition of `if`, `while` and `switch` is the whole expression from its `(`, so `if (a) || (b)` reads as one condition.
  - Digits before a letter or `_` start a word, such as the sprite constant `4_M_CACTUSMAN20`.
  - `set` takes a reference that is not a variable, such as `set getelementofarray(getarg(0), .@i), 1;`. It is a `SetRef` statement. Item scripts still refuse it.
  - Any one character after an assignment ends it, as `parse_line` skips that character without checking it (script.cpp 1525). So `for (.@i = 0, .@i < 3; .@i++)`, `.@x = 1:` and `.@x = (1));` parse as rAthena reads them.
- `npc.go` places NPCs and shops from `npcs.json`, its part files of the `quests`, `warps` and `events` folders (review decision 55), and the barter shops of `shops.json`, and writes core's `data/npcs.yml`. The part files come after `npcs.json`, so the record names of its NPCs do not change. Shops become data. A script NPC is placed when its own script converts whole. A duplicate uses its source's script, which converts even when the source is not placed, such as a source without a map. NPCs on instance maps, such as `1@tower`, are not placed, as wAthena has no instances yet.
- `npcstatus.go` converts `sc_start`, `sc_start2`, `sc_start4`, `sc_end` and `getstatus` in NPC scripts. NPC scripts set `cannot_be_avoided`, as rAthena's default flag for NPCs is `SCSTART_NOAVOID`.
- `npclua.go`, `npcexpr.go` and `npcscript.go` translate scripts to Lua with the API of proposal 0002: conversations, `wa.variables`, zeny, items and save points. Labels become Lua labels, and a function's `end` becomes `R.stop()`.
- Event labels run on into the next label until an `end`, as in rAthena. These event labels convert:
  - Every label that starts with `On` is an `npc_event` handler of its name, as rAthena's `ev_db` lists them, so `donpcevent` reaches custom labels such as `OnEnable`, and `OnInit`, clock and timer labels too (review decision 58). Each label is a local function of the setup function, which the handler and the label's other uses call.
  - `OnInit` runs at the end of the NPC's setup function, through its function. An `OnInit` that waits or shows a dialog does not convert: it runs without a player.
  - Clock labels become schedules: `OnClockHHMM` and `OnHourHH` daily, `OnMinuteMM` hourly, and `OnSunHHMM` to `OnSatHHMM` weekly. `OnDayMMDD` does not convert, since the API has no yearly schedule.
  - A label that a `monster` command of the same NPC names runs when each of its monsters dies, with the player that killed it.
  - `OnTouch` becomes a `touch` handler, and `OnTouch_` a handler through `R.touch_one`, which runs it for one player at a time, not for a hiding or dead player, and for the next player in the area when that one leaves (`npc_touchnext_areanpc`). `OnTouch_` wins over `OnTouch`, as in rAthena. The line's span becomes the record's `touch` field (review decision 55), and a line without a sprite (-1) gets `sprite: none` (review decision 58).
  - A touch handler runs in a conversation with the player (review decision 56), so an `OnTouch` or `OnTouch_` part with a dialog converts, and so does one that calls a function with one. `R.touch_one(fn, true)` marks a part with a dialog: it does not run for the next player already in the area, who has no conversation, and runs for the next player who comes in instead.
  - `OnTouchNPC` is a `monster_touch` handler too. Its part runs with no player: rAthena attaches the monster, which a converted script cannot read.
  - The labels that rAthena runs for the players of every map do not convert: `OnPCLoginEvent`, `OnPCLogoutEvent`, `OnPCLoadMapEvent`, `OnPCBaseLvUpEvent`, `OnPCJobLvUpEvent`, `OnPCDieEvent`, `OnPCKillEvent` and `OnNPCKillEvent`. An NPC hears only the players of its own map (decision 0062). The labels of systems wAthena does not have, such as `OnAgitStart` and `OnInstanceInit`, and `OnInterIfInit` and `OnInterIfInitOnce`, do not convert either.
- `jobchange <job>,Upper`, rAthena's `Job_Change`, converts to `player:change_job`'s `keep_line` (review decision 58), so the function converts whole. A fixed upper of 0 or -1 is the plain change. Other second arguments do not convert.
- `skill` and `addtoskill` convert to `player:give_skill` (review decision 57), so the renewal first job changers convert:
  - `SKILL_PERM` (0) is `"permanent"`, `SKILL_TEMP` (1) `"temporary"`, `SKILL_TEMPLEVEL` (2) `"temporary_add"` and `SKILL_PERM_GRANT` (3) `"permanent_grant"` (review decision 58).
  - Without a flag, `skill` is `"temporary"` and `addtoskill` is `"temporary_add"`, as in rAthena.
  - A skill by name or by a fixed ID converts. A computed skill or flag does not.
- `percentheal` with a negative amount converts to `player:heal_percent`, which takes that percent of the maximum and never takes HP below 1 (review decision 56). rAthena kills at -100.
- `monster` converts on the NPC's own map, with the monster's own name, the default size and AI, and an event label of the NPC or none. `mobcount` converts for such a label. `killmonster` does not convert.
- `npcparty.go` converts the party commands and reads to `player.party` and `wa.parties` (proposal 0002, review decision 27). A party ID of `getcharid(1)` becomes `player.party`, and any other ID `parties.get(id)`. The write commands convert as statements for the attached player only. `getpartymember` converts for names, and `$@partymembername$` and `$@partymembercount` read its result in the same function. Character IDs, account IDs and the leader's job, map and level do not convert.
- `npcstorage.go` converts the storage commands to the calls of proposal 0002, review decision 29: `openstorage` and `openstorage2 0` to `player:open_storage()`, `storagecountitem`, `cartcountitem` and `guildstoragecountitem` to `count_item` with `from` or `guild:count_item` (-1 where rAthena gives it), `storagedelitem` and `cartdelitem` to `take_item` with `from`, and `getitembound` to `give_item` with `bound`. `basicskillcheck()` reads its rule with `rules.get("basic_skill_check")` (review decision 32). `countbound`, the `2` forms, other storage IDs and modes, and other accounts do not convert, with the reason in the report.
- `checkre(0)` is the converter's mode, as rAthena's `RENEWAL` define. `checkre(1)` to `checkre(5)` read the ruleset flag of their define with `rules.is`: `cast_time`, `level_penalty_drop`, `level_penalty_exp`, `level_damage_mod` and `aspd` (review decision 32). `TestRuleReadsConvert` checks them.
- `npcguild.go` converts the guild reads and commands to `player.guild` and `wa.guilds` (proposal 0002, review decision 28). A guild ID of `getcharid(2)` becomes `player.guild`, and any other ID `guilds.get(id)`. `guild_has_permission` converts for a fixed permission, and `getguildmember` for names, as `getpartymember` does. `guildgetexp` converts for the attached player's guild. `guildopenstorage` calls `R.guild_storage`, which uses `player:open_guild_storage()` and returns rAthena's `GSTORAGE_` codes. `guildopenstorage_log` calls `R.guild_storage_log`, which uses core's `wa.internal` module and says that the log is not available in other mods. Character IDs, guild skill raises, castles and the other guild commands do not convert, with the reason in the report.
- `npcshop.go` converts shops, currencies and mail to proposal 0002, review decision 30:
  - `shop` lines keep the list form. `itemshop`, `pointshop`, `cashshop`, `marketshop` and barter shops use the table form, which players cannot sell to, as in rAthena.
  - An `itemshop` price is an amount of its item, a `pointshop` price an amount of its variable's currency, and a `cashshop` price an amount of `cash`. A `marketshop` item has a zeny price and its stock, and no stock for -1. A barter item costs its zeny and items, with its stock when it is above 0.
  - A barter item that is refined, that takes a refined item or more than 5 kinds of items, or that the barter sells a second time, does not convert. Neither does a `marketshop` item that starts with no stock, or a second entry for an item in a table shop. The shop then converts partly.
  - A `pointshop` variable becomes a currency: `#CASHPOINTS` is `cash`, `#KAFRAPOINTS` is `kafra`, and any other variable is a new record of core's `data/currencies.yml` with an ID from 3, owned by the account for `#` and `##` variables and by the character otherwise. A temporary variable does not convert.
  - Reads of these variables become `player:get_currency`. `x += n`, `x -= n`, `x = x + n` and `x = x - n` become `give_currency` and `take_currency`, or `R.add_currency` for a computed amount. Other assignments become `R.set_currency`, which gives or takes the difference.
  - `callshop` opens the converted shop or barter by its record name. `npcshopupdate`, `npcshopadditem` and `npcshopdelitem` use `world.get_shop`: `set_stock` for a stock, `add_item` for a new price or item, and `remove_item`. A new price converts only for an item the shop's line sells, and a new item only when the shop does not sell it already.
  - `mail` becomes `player:send_mail`, with `R.mail_items` reading the item and amount arrays when the script runs. `openmail`, `searchstores` and `buyingstore` become `player:open_mail()`, `player:search_stores` and `player:open_buying_store`.
  - `npcshopitem`, `npcshopattach`, `sellitem`, `stopselling`, mail with refine, bound, card or option arrays, and `searchstores` on another map do not convert, with the reason in the report.
- `quests.go` converts rAthena's quests from `quests.json` to core's `data/quests.yml` (proposal 0002, review decision 45, [decision 0043](../../docs/decisions/0043-quests.md)). A record's name is the quest's ID. A `TimeLimit` with "+" becomes a duration, such as `3h`, and one without becomes `{ at, days }` or `{ at, weekday }`. Races, sizes and elements take the names of `wa.races`, `wa.sizes` and `wa.elements`. `wactl convert quests --report docs/generated/quests-<mode>.md` writes the coverage report, which `TestQuestReportsCurrent` checks.
- `npcquest.go` converts the quest commands to the quest calls of review decision 45:
  - `setquest`, `completequest`, `erasequest` and `changequest` become `player:add_quest`, `player:complete_quest`, `player:remove_quest` and `player:change_quest`, with the quest's ID.
  - `checkquest` becomes `R.checkquest` and `isbegin_quest` `R.isbegin_quest`, which return rAthena's numbers. rAthena counts a quest without a time limit as timed out for `PLAYTIME` and `HUNTING`, since its end time is 0. The converter passes whether the mode's quest has a limit; for a computed ID it passes nil, and the quest's own limit decides.
  - A fixed ID that the mode's `quest_db` lacks converts to what rAthena does: the commands become a comment, as rAthena only logs an error, `checkquest` is -1, and `isbegin_quest` 0.
  - `showevent` becomes `npc:show_quest_icon` with the icon's name. `QTYPE_DAILYQUEST`, `QTYPE_NONE` and other values remove the icon, as `buildin_showevent` at PACKETVER 20211103. A minimap mark color other than `QMARK_NONE`, a computed icon, and every command for another character do not convert.
- `rathena.lua` is `scripts/lib/rathena.lua`: helpers for what Lua lacks, such as rAthena's arrays, `menu`, `getarg`, `input` with its bounds, `getitem` and `delitem` with a computed amount, which do nothing for 0 or less, the map and monster commands of `npcmaps.go`, `OnTouch_` (`R.touch_one`), `pc_ishiding` (`R.hiding`), the NPC-to-NPC commands (`R.npc_view`, `R.fire`, `R.doevent`, `R.npc_of`), and `mapannounce` of a computed text, which leaves out an empty one. `R.checkquest` and `R.isbegin_quest` read a computed quest ID that `data/quests.yml` lacks as a quest the player does not have, as `quest_check` does.
- Kafra pushcart rental converts: `F_KafCart` reads `BaseClass`, `checkcart()` and `getskilllv`, takes the Free Ticket for the Cart Service or the fee, and calls `setcart`, which is `player:set_cart`. With Niflheim's negative `percentheal`, every Kafra converts fully.
- Calls by name follow rAthena's `parse_callfunc` (script.cpp 960 to 1000). A script command wins: `builtins.go` lists rAthena's commands, made from the `BUILDIN_DEF` lines of script.cpp. Then a local function of the script runs as `callsub` runs a label, and a global function as `callfunc`, such as `F_InfoBoard;` and `unknown_d(...)`.
- Local functions (`function Name { ... }`) become Lua local functions of the part that calls them, with their own `.@` scope and `getarg`, as rAthena's `callsub`. rAthena jumps over a body where it is written, so the converter writes nothing there.
- `callsub` finds its label anywhere in the script's top level, and its function runs from the label on, through later event labels, as rAthena's does.
- Each Lua function leaves out the parts of the top level that it cannot reach (`reachable`). A part is reached when the part before it does not leave, or when a `goto` or a `menu` of a reached part names its label. A part leaves when it ends with `end`, `close`, `return` or `goto`, with `callsub` of a label whose part has no `return`, with an `if` and `else` that both leave, or with a `switch` whose cases cover every value and each leave. A `switch` on `select` of fixed options covers 1 to their count, as a player who cancels the menu ends the script. So a `callsub` part after an `end`, with its `getarg`, is no longer part of the click handler.
- A label inside a block converts when every jump to it comes from that block or a block in it, as Lua's `goto` sees labels. A jump from outside does not convert.
- A global function that writes `set getelementofarray(getarg(n), i), v;` writes its caller's array: rAthena passes a variable argument as a reference (`buildin_callfunc`). The caller passes its `.@` or `.` array table for argument n. So `F_time_limit_recorder` converts, and its callers are placed. They convert partly, as its `consumeitem` part does not convert yet. Other reference arguments, such as `set getarg(0), v;`, do not convert.
- `npcworld.go` converts the NPC-to-NPC commands onto review decision 58's API ([decision 0062](../../docs/decisions/0062-npc-api-group-1.md)):
  - An NPC named by a fixed string is found by its record name with `world.get_npc` when the script runs. `strnpcinfo(0)` or `strnpcinfo(3)` joined with `"::OnX"` is the NPC itself, the duplicate that runs the script. A command on an NPC that does not exist does nothing, as rAthena only logs an error, and `getvariableofnpc` ends the script, as rAthena's does.
  - `enablenpc`, `disablenpc`, `hideonnpc` and `hideoffnpc` become `show`, `hide` and `set_hidden` through `R.npc_view`. `cloakonnpc` and `cloakoffnpc` become `set_cloaked` for everyone, or for the attached player with `getcharid(0)`, and `cloakonnpcself` and `cloakoffnpcself` for the attached player, through `R.npc_cloak_for`, which does nothing without one. `isnpccloaked` is `R.is_cloaked`. `unloadnpc` is `remove`. rAthena refuses to unload the NPC that runs the script, so that converts to nothing, and an NPC with duplicates does not convert, as rAthena unloads them too.
  - `donpcevent "NPC::OnX"` is `R.fire`, `donpcevent "::OnX"` is `world.fire_npc_event`, a computed name is `R.donpcevent`, and a name without `"::"` finds no event, as in rAthena. `cmdothernpc` fires `OnCommand<command>`. `doevent` is `R.doevent`, for an NPC on the map of the NPC that runs it: the player must be on the NPC's map.
  - `getvariableofnpc(.x, "NPC")` reads and `set getvariableofnpc(...)` writes an NPC variable of `wa.variables`. Before it converts, the converter reads every script for the `.x` that `getvariableofnpc` reaches, by NPC, or for every NPC when the name is computed. Those `.x` become NPC variables in their NPC's own script, so every zone reads one value. Other `.x` stay locals of the setup function.
  - A script that duplicates run keeps every `.x` as an NPC variable of its source, `NpcSource`, so the source and its duplicates share them, as `npc_parse_duplicate` copies the script and its `script_code->local` (npc.cpp 4596). `getvariableofnpc` of a duplicate reaches its source's.
  - A name with a `::` unique name, such as `Guard#east::G1`, keeps its `#` part in the record's `display_name`, so `strnpcinfo(0)` and `(2)` read it.
  - `$@x` variables are temporary server variables, also by a computed `getd` and `setd` name. A number assigned to a string variable becomes its digits, and a string assigned to a number variable is read as `conv_num` does.
  - `strnpcinfo(0)` to `strnpcinfo(4)` are `npc.full_name`, `name`, `hidden_name`, `unique_name` and `map`.
  - `getcharid(0, name)` and `getcharid(3, name)`, and `convertpcinfo`, read a player of the map through `maps.find_player` and `maps.find_player_by_id`, or give 0 and "" without one. `getpartymember` types 1 and 2 read `party:get_member_list`.
  - A script NPC without a map is placed with a record that has no map, and runs in the start map's zone. One whose script does nothing is not placed. A line that starts `DISABLED`, `HIDDEN` or `CLOAKED` gets `state`. A view of -1 is `sprite: none`, with or without a touch area. `HIDDEN_NPC` is no longer used.
  - `atcommand` and `setbattleflag` are refused by review decision 58, with the decision in the report.
  - These do not convert: `getnpcid` as a value, which only the unit commands of `npcpresent.go` take, `awake`, `attachrid`, `sc_start2` on another character, `doevent` in a function or to an NPC on another map, and `getvariableofnpc` of an element of a variable that is not an array.
- `npcpresent.go` converts the presentation and quest icon commands onto review decision 58's areas B5 and B6 ([decision 0063](../../docs/decisions/0063-npc-api-group-2.md)):
  - A command on another NPC goes through `R.npc_view`, which finds the NPC by name when the script runs and does nothing when it does not exist. An empty name of `npctalk` and `classchange` is the NPC itself, through `R.or_self`.
  - A game ID argument converts when it is the attached player (`getcharid(3)`, `playerattached()`, `getattachedrid()`, or 0 for `unitwarp`), the NPC itself (`getnpcid(0)`), or an NPC by name (`getnpcid(0, <name>)`). A variable whose every assignment is one of the `getnpcid` forms, such as `.@npc_id = getnpcid(0);`, stands for that NPC. Its assignment converts to a comment, and any other read of it does not convert.
  - `npctalk` with `bc_map`, `bc_all`, `bc_self` and a color becomes `npc:say_aloud` with `to` and `color`. A computed line goes through `R.say_aloud`, which leaves out an empty line. `bc_self` does nothing without an attached player.
  - `unittalk` of the attached player becomes `player:say_aloud`, with `to = player` for `bc_self`. A leading `strcharinfo(0) + " : "` is left out, as the client shows the speaker's name. `unittalk` of an NPC does not convert: it reaches the chat range, and `npc:say_aloud` reaches the NPC's view.
  - `emotion` on the player or an NPC, `specialeffect` with `AREA`, `ALL_SAMEMAP` or `SELF` on the NPC or another NPC, `specialeffect2` with a target, and `removespecialeffect` and `removespecialeffect2` with `AREA`.
  - `setunittitle`, cut to 23 bytes as `safestrncpy` does (`R.title` for a computed title), `setnpcdisplay` through `R.npc_display`, which gives 1 for an NPC that does not exist, `classchange` for the area, and `setunitdata` with `UNPC_CLASS`, `UNPC_SEX` and the `UNPC_` looks.
  - `unitwalk` of an NPC, as a command or a value, `unitwarp` of the attached player or of an NPC on its own map, `unitstopwalk`, `npcspeed`, `npcwalkto`, `npcstop` with its default flags, and `movenpc` without a direction.
  - `unitwalk` goes through `R.unitwalk`, which starts the walk after 50 ms and refuses a second forced walk until the first reaches its cell, as `unit_delay_walktoxy_timer` and `ud->state.force_walk` (script.cpp 20015, 20032). It gives 1 when it starts the walk: rAthena checks `unit_can_reach_pos` first. `unitstopwalk` and `npcstop` go through `R.npc_stop`, which ends the forced walk too.
  - `progressbar_npc` with the color that rAthena's `strtol` with base 0 reads, so `"FFFF00"` is 0. `npcskill` casts on the attached player, and `skilleffect` shows on the player or an NPC.
  - `soundeffect` and `soundeffectall` with type 0 or 1 and a map or none, `playbgm`, and `playbgmall` with a map. A file name becomes an asset name: the path in lower case without `.wav` or `.mp3`.
  - `dispbottom`'s color, `showdigit`, `viewpointmap` types 1 and 2, `questinfo`, whose condition string parses as rAthena script and becomes a function of the player, `questinfo_refresh`, `open_quest_ui` with a fixed quest, and `showevent`'s mark.
  - A line whose view is a monster, by number or name, or a job is placed with the number, as rAthena takes any class.
  - These do not convert: `unittalk` of an NPC, the send targets other than area, map and self, `removespecialeffect` for one player, a size of `setnpcdisplay`, `classchange` for one player, other `setunitdata` types, `unitwalk` with an event label and `unitwalkto`, `unitwarp` of an NPC to another map, `movenpc` with a direction, `npcstop` with other flags, `soundeffect` type 2, sounds and music on a part of a map, `playbgmall` without a map, `questinfo` with `QTYPE_NONE` or a computed condition, and `open_quest_ui` with a computed quest.
  - A `sleep` in an event label converts to `R.sleep`. rAthena's script sleeps even without a player. Here an event without a player has no conversation, so `R.sleep` stops it with "which wAthena does not have yet".
- `npctimer.go` converts the NPC timer: `initnpctimer`, `startnpctimer`, `stopnpctimer`, `setnpctimer`, `getnpctimer` and the `OnTimer<n>` labels (script.cpp 11710 to 11890, npc.cpp 1470 to 1735). `R.npc_timer` keeps rAthena's state: the tick of the last start, stop or label, and when it ran from it, by the server clock (`wa.clock`, review decision 58), the next label, and labels by tick that run without a player.
  - `getnpctimer(0)` is the tick, as `npc_gettimerevent_tick`. `startnpctimer` resumes from the tick where `stopnpctimer` stopped, as `npc_timerevent_start`.
  - The tick runs while the map has no players, as rAthena's. The labels wait on `timers.after`, which follows the zone clock: a label that came due while the map slept runs when the map wakes, and the labels after it that came due run with it, in order.
  - These forms do not convert: another NPC's timer, an NPC's own name in a script that its duplicates run, where the name is the source's, a timer attached to the player (an attach flag other than 0), `addtimer` and `deltimer`.
- `npcgroup3.go` converts the player, item and clock commands of review decision 58, areas B7, B9 and B10, for the attached player only:
  - B7: `getexp` and `getexp2` to `player:give_exp`, `heal`, `Hp = n` to `player:set_hp`, `Weight`, `MaxWeight` and `SkillPoint`, `setpcblock` and `getpcblock` by `PCBLOCK_` bit (`R.set_pc_block` and `R.pc_block` for computed ones), `disable_items` and `enable_items` through `R.lock_items`, `nude`, `pushpc` through `R.pushpc`, `transform`, `readbook`, `getsavepoint`, `getinventorylist` (the `@inventorylist_` arrays the script reads, through `R.inventory_list`), `setlook` and `getlook` of the hair, colors and headgear, `checkoption`, `readparam` of a named parameter, `getgmlevel`, `eaclass`, `roclass`, `checkdragon`, `setdragon` of the green dragon, `checkmadogear`, `setmadogear` of `MADO_ROBOT`, `checkwug` and `ismounting`.
  - B9: `getitem2`, `getitembound2` with a refine, attribute or cards, `getnameditem`, `countitem2` of identified copies that are not broken, `rentalcountitem`, `rentitem` and `rentitem2`, `makeitem` and `makeitem2`, `getiteminfo`, `getitemslots`, `getequipisenableref`, `getequippercentrefinery`, `getequiprefinecost` of `REFINE_COST_NORMAL`, `successrefitem`, `downrefitem`, `failedrefitem`, `delequip`, `getbrokenid`, `repair`, `repairall`, `consumeitem` and `mergeitem`. Computed cards go through `R.cards`, which leaves out empty slots.
  - B10: `gettimetick`, `gettime`, `gettimestr` and `getbattleflag` of the exp rates, the look limits, `feature.barter` (1), and `feature.bgqueue`, `feature.refineui`, `feature.achievement` and `feature.stylist` (0, systems that do not exist).
  - These do not convert: another character's ID, `active_transform`, `transform` with a status, `setlook` of the weapon, shield, garment or body, the enriched chance and the HD and Enriched costs, which the refine data lacks, a forged, named or pet item's mark in card 1, `getinventorylist`'s random options, `readparam` by number, other battle flags, `jobcanentermap`, which needs WoE:TE map flags, a dragon of another color and the Madogear suit.
- `npcmaps.go` converts the map, area and monster commands of review decision 58, area B8 ([decision 0065](../../docs/decisions/0065-npc-api-group-4.md)):
  - `monster` and `areamonster` on any map, through `R.monster` and `R.areamonster`, with their name, size and AI. A cell that units can walk on places each monster there, and any other cell, such as 0,0, is a random one. A monster that does not exist, or a random monster group's negative ID, spawns nothing.
  - The event label becomes spawning.monsters' `label`: a label of the NPC itself, or `"<NPC>::<label>"` of another NPC, whose name becomes its record's. A label made when the script runs, such as `.npc_name$ + "::OnMyMobDead"`, goes through `R.label`. In a script that duplicates run, the NPC's own name is the source's, as rAthena reads it.
  - `killmonster` and `killmonsterall` with their type, as `maps.remove_monsters`. `"All"` is `scripted`. `mobcount` is `maps.count_monsters`, with `"all"` for every monster, and -1 for a map that does not run.
  - `getmapusers` and `getareausers`, `mapwarp` with its guild or party, `areawarp` with its second area, `warpparty` to a map and a cell, and `areaannounce` without its colors, as mapannounce.
  - `setcell` and `checkcell` of the kinds the server has, `setwall`, `delwall` and `checkwall` over `maps.set_cells`, with the walls by name in a temporary server table, `setmapflag`, `removemapflag` and `getmapflag` of `mf_nomemo`, `getfreecell` with its flags 1 and 2, and `getmonsterinfo`.
  - A command on a map that does not run does nothing, as rAthena's, through `R.on_map`.
  - These do not convert: `"this"` as a map, `areawarp` to `"Random"`, `warpparty` to `"Random"`, `"SavePoint"`, `"SavePointAll"`, `"Leader"` or `"RandomAll"`, or from one map with a range, cell kinds and map flags whose systems do not exist (the report gives each reason), and the unit commands on a monster's game ID (`unitkill`, `unitwarp`, `unitskillusepos`, `setunitdata` with `UMOB_`), as `$@mobid` holds no monster handles.
- `npcbuiltins.go` converts commands onto API that exists:
  - Equipment reads by `EQI_` slot over `player:get_equipped`: `getequipid`, `getequipname`, `getequiprefinerycnt`, `getequipisequiped`, `getequipweaponlv`, `getequiparmorlv` and `getequipcardid`. `isequipped` converts for at most five fixed items that are not cards. rAthena matches a card once per combo through `setitem_hash`, and from the sixth argument it skips slots by the argument's place.
  - Strings and numbers, with C's rules in `R`: `atoi`, `strtol`, `compare`, `charat`, `strtoupper`, `strtolower`, `substr`, `insertchar`, `delchar`, `replacestr`, `countstr`, `pow` and `distance`.
  - `sprintf` with the conversions `%d`, `%i` and `%s`. A fixed format becomes `string.format`, with the values' types checked. `R.sprintf` reads a computed format when it runs, and raises an error for another conversion or a value of another type.
  - Arrays of the script (`.@` and `.`): `inarray`, `copyarray` and `explode`.
  - `getmapxy` of the attached player or the NPC itself, `warp` to a computed map (`R.warp` checks `Random`, `SavePoint` and `Save`), `getgroupitem`, `getskilllv` of a computed skill ID, `mesitemlink` with brackets, and `debugmes` as a comment.
  - `getd` and `setd`. A fixed name is that variable. A computed name converts when its fixed start fixes the scope (none, `@`, `#`, `##` or `$`), and no currency, parameter, constant or skill starts the same way. `R.getd` and `R.setd` read the rest when the script runs, as `getd`'s `sscanf` does, and declare the variable then. A computed `.@`, `.`, `$@` or `'` name does not convert.
- A quest command with a computed ID calls `R.quest`, which does nothing for a quest that `data/quests.yml` lacks, as rAthena only logs an error.
