# wAthena v0.1.0

The first release of wAthena, for server owners. Date: 2026-10-20.

## What wAthena is

- wAthena is server software for running a Ragnarok Online world. It is a rebuild of [rAthena](https://github.com/rathena/rathena) with a Go server, Lua mods and a web client.
- You run the server yourself. The project runs no server, world or beta of its own.
- wAthena ships no game art. It ships a small placeholder pack, enough to check that a server runs. For real art, and for a classic world, you bring your own Ragnarok Online client files (GRF).
- Players play in a Chromium-based browser, such as Chrome, Edge or Brave. They need no download. Firefox and Safari are not supported.
- A release is a git tag. The project publishes no binaries, images, signatures or software bill of materials. You build from the tag with the setup guide.
- wAthena is not affiliated with or endorsed by Gravity or the rAthena team.

## What is in this release

### World modes

A world's mode is fixed when you make it. Both modes are in every build.

- **Procedural, the default.** Fields, towns and dungeons are generated from a secret seed. Dungeons rotate and seasons change. It runs with the placeholder pack or with your client's art.
- **Classic.** rAthena's maps, NPCs and monster spawns, from your client's GRF files. In short:
  - 4,982 of 15,337 NPC lines are placed.
  - 54 of 55 Kafras are placed, and every placed Kafra converts fully: storage, teleport, save, pushcart rental and Niflheim's HP and SP loss.
  - 264 of 710 job change NPCs are placed.
  - Instances, guild sieges, battlegrounds and the MVP tomb are not built.
  - [docs/generated/classic-coverage.md](../generated/classic-coverage.md) lists what does not convert, by folder and by cause.

### Rulesets

- The renewal ruleset is the default, and the ruleset classic mode ships with.
- Pre-renewal is experimental until it matches rAthena's pre-renewal rules. `waserver` warns at start when a world uses it.

### Accounts

- Account pages for signup, login and characters, with Argon2id passwords.
- Two-factor login with TOTP codes, recovery codes and passkeys.
- Players can download their data and delete their accounts. Deletion waits 14 days and can be cancelled.
- Players can report and block other players.

### Staff tools

- Admin screens at `/admin`, for staff with a second factor at login.
- Roles: owner, admin, game master and moderator, with permissions you can change in the config.
- Player search, item history and restores, reports, mutes, jails, kicks and bans.
- GM commands in the game, such as `@warp`, `@recall`, `@mute` and `@jail`.
- World, events and mods screens: announcements, planned restarts, event runs and mods per map.
- Every staff action is written to an audit log.

### Mods

- Mods are Lua scripts and YAML data, run in a sandbox with CPU and memory limits.
- The Lua API is version 1.0. A mod's manifest must name `api: 1.0`, or a range that includes it.
- Mods ask for permissions, and the owner approves them.
- mods/README.md is the guide. docs/generated has the API reference.

### Backups

- The Compose stack makes an encrypted backup once a day, with age, to a key only you hold.
- Each backup has a manifest with its hash and counts.
- `wactl world verify-backup` restores a backup into a temporary database and checks it, on your own machine or, if you choose, on the server.

### Retention

- The server deletes old personal data once a day: login records after 90 days, chat after 30, item and zeny logs after 180, and the staff audit log after 730.
- You can change each period in `waserver.yml`. Players see the periods in effect on `/account/privacy`.

### Measured capacity

- 250 players online met every performance budget, in a procedural world with PostgreSQL.
- The machine was an Apple M2 with 8 GB of memory, shared with desktop apps and Docker. The server used under half a core. Memory set the limit.
- 500 players met the budgets in some scenarios and not in others. The project makes no claim above 250.
- Measure your own machine with `wabots` before you open a world. The setup guide shows how.

## Install

Follow [docs/guides/setup.md](../guides/setup.md). It takes you from an empty Linux machine to a running world with Docker Compose, PostgreSQL 18 and Caddy.

```sh
git clone --branch v0.1.0 https://github.com/lxsmnsyc/wathena.git
cd wathena/deploy/compose
```

Link your players to [docs/guides/players.md](../guides/players.md), or copy it and fill in your server's name.

## Known issues

### Security

From the [security review of October 2026](../security/review-2026-10.md).

Known issues:

- The account database role can make characters with any start values. A fix needs the start config in the database.
- The files in `deploy/compose/secrets` have mode 644. The folder's mode 0700 keeps other users out, so keep that mode when you copy the stack.
- Database traffic inside the Compose network is not encrypted. Only the stack's containers are on that network.
- Backups and their manifests are not signed. Restore only copies you made yourself, kept where others cannot write.
- `scripts/release.sh` checks only that Go, zig and pnpm are on the path, not their versions.

Accepted risks:

- Mod packages without a signature install with a note. Compare the checksum with one the author publishes elsewhere, or use `--public-key`.
- The game database role can drop item and zeny log months older than 30 days, before the period in the config.
- `/gen/maps` shows every procedural map's names, bands and places. Spawns stay secret.
- Future seasons' terrain can be computed from public data. Their spawns cannot.
- Staff of the same role can sanction each other.
- A game session keeps the staff role it had at login until the next login.
- The signup captcha has no real provider. Signups are limited per address: 3 at once, then 1 every 10 minutes.
- The weak password check uses a list of common passwords, not a breach list.
- A proxy that is not on loopback and not in `trusted_proxies` makes all its players one address, which the connection limits refuse after 32. Set `trusted_proxies`.

### Classic mode

From decisions [0052](../decisions/0052-classic-mode-part-b.md) and [0053](../decisions/0053-skill-command.md):

- The Thief job change does not convert. The Thief Guide uses `jobname`, which the converter does not support.
- `percentheal -100` kills in rAthena and leaves 1 HP in wAthena. This changes the Poison Bottle.
- A touch area with a dialog runs for one player at a time. When that player leaves, it does not run for the next player already in the area, only for the next player who comes in. rAthena shows the dialog to the player already in the area.
- An NPC with a touch area and no touch label does not open its dialog when a player steps in. rAthena opens it.
- An NPC without a sprite answers only within 15 cells. rAthena answers from anywhere.
- Permanent skills granted by NPCs that survive job changes and resets (`SKILL_PERM_GRANT`) are not supported.
- Temporary skill levels and item skills are not shown in the client's skill list.
- `player:get_skill_level` reads learned levels only. rAthena's `getskilllv` counts item and temporary levels too.

### Server

From [decision 0054](../decisions/0054-restores-logins-and-lua-time-limits.md):

- The Lua time limit is a 30 second backstop per call. The CPU budget measures normal work. A mod that compares long strings in a loop can hold its zone for up to 30 seconds per call.
- On a machine that stalls, the 30 second backstop can still end a zone's Lua state at start. On a loaded test machine with all 988 kRO maps, it hit 63 zones.
- An admin API call that changes the world can report an error for a change that did happen, when its request ends first. Restores are fixed. Check the result before you try again.

### Platforms

- The server was built and tested on an Apple M2 (arm64), in Docker on Linux arm64, and as amd64 under Rosetta. It has not been tested on a real amd64 machine. The generated maps match on both architectures in tests.
- The client supports Chromium-based browsers only.

## Checks on this release

The release commit passed these checks on an Apple M2 with 8 GB, on 2026-10-20:

- `scripts/check.sh` default steps: vet, test (with the race detector), mods, lua, loadtest, schema, queries, lint, security, fuzz, client, tinygo and gen.
- `scripts/check.sh e2e`: the end-to-end tests with PostgreSQL 18, with the 30 minute exit check.
- `scripts/check.sh browsers`: the client in Chromium against `waserver` and PostgreSQL. The kRO check is opt-in and needs a full kRO asset build, so it did not run.
- `scripts/compose-smoke.sh`: the Compose stack from new volumes, with a backup, its check and a restore.
- Fuzzing:
  - Every fuzz target ran for 10 seconds in the fuzz step.
  - The targets that read bytes a remote player sends ran for 10 minutes each: `FuzzClientMessage` (every WebSocket message, `Hello` too), `FuzzTokenHash` (session and game ticket tokens), `FuzzProcess` (guild emblem uploads) and `FuzzSearch` (walk paths to the cells players ask for).
  - `FuzzSearch` found a search from cell (0, 0) that never ended. It is fixed, with a test.

## Reporting security problems

Do not open a public issue. Report privately through GitHub's private vulnerability reporting, as [SECURITY.md](../../SECURITY.md) explains. v0.1.x gets security fixes as patch releases.
